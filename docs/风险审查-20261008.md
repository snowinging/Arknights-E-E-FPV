# Arknights_E_E_FPV 全项目风险审查

审查时间：2026-10-08
审查范围：`src/games/endfield-enhancer-FPV/` 全部功能代码 + 构建产物 + 游戏目录实际部署物
审查目的：账号安全（ACE / 游戏用户协议），以及作为公开项目对使用者的责任

---

## 一、结论摘要

| 等级 | 项目 | 说明 |
| --- | --- | --- |
| 高 | 注入与内联钩子 | 42 处 Detours，其中绝大多数落在 `GameAssembly.dll` 与游戏 C# 程序集的方法入口上，等于对游戏代码做在线补丁 |
| 高 | 玩家状态写入 | `PlayerController.AddActionEnableMask/RemoveActionEnableMask`、`RotatorComponent.SetRotation`、实体姿态恢复 |
| 高 | 相机脱离角色 | 自由相机 / FPV 可让视点离开角色可达范围，穿墙、飞出地图 |
| 低 | 光照体积流送跟随相机 | 只调引擎自带接口置一个模式标志，让光照体积(IV)的流送中心跟随相机（不改地形/物件 LOD） |
| 中 | 实体加载与 LOD | NPC 剔除、LOD 降级、加载距离、世界距离调整（改变实体加载行为） |
| 中 | 渲染管线接管 | 覆盖 SSR / HDR / 帧生成 / DLSS（Streamline）、Vulkan 交换链与 barrier |
| 低 | 表现层 | UI 隐藏、截图、FPS 解锁、窗口增强、飞行 HUD |
| 无 | 作弊类功能 | 未见无敌、伤害、金币、掉率、自动拾取、加速、瞬移等 |

正面发现（都很重要，建议写进 README）：

1. **没有任何网络代码**——无 WinHTTP / WinInet / WSA / socket，无外部请求，无遥测。
2. **没有跨进程行为**——无 `OpenProcess` / `ReadProcessMemory` / `WriteProcessMemory` / `CreateRemoteThread`。
3. **没有全局输入钩子**——`SetWindowsHookEx` 全部是线程级（`WH_GETMESSAGE` / `WH_CALLWNDPROC`，目标为自己创建的线程），不监听其它进程。
4. **不碰反作弊**——全项目没有任何 ACE / 反作弊模块名、没有特征码扫描、没有自我隐藏、没有反检测对抗。
5. **不改存档、不写 PlayerPrefs**——只有自己的 `AEEF.ini` 与截图文件落盘。
6. 输入层隐身代码已于本次审查前整体删除（204 行），插件现在不修改任何输入相关行为。

## 二、检测面（能被看见的东西）

### 1. 内联钩子

| 文件 | Detour 站点 | 目标 |
| --- | --- | --- |
| npc_offcamera.hpp | 11 | Gameplay.Beyond（NPC/LOD 管理器） |
| hdr_output.hpp | 7 | Vulkan 交换链 / barrier / descriptor |
| enhancer.hpp | 7 | SSR、Streamline、DLSS、渲染路径 |
| camera.hpp | 6 | Cinemachine、CameraState |
| screenshots.hpp | 5 | 截图相关渲染路径 |
| screenshot_observer.hpp | 3 | 渲染管线 |
| world_distance / uncensor / ui_visibility | 各 1 | 世界距离、文本、UI |

目标模块分布：`GameAssembly.dll` 32 处、`Gameplay.Beyond.dll` 10 处、Unity 各模块 15 处、`sl.interposer.dll` 2 处、`Lua.Beyond.dll` 与 `XLua.Runtime.dll` 各若干。

含义：这些不是"只改画面"的钩子，而是改写了游戏自身模块的代码页入口。任何带内核驱动的反作弊（ACE 属于此类）都有能力发现：
- 游戏模块 `.text` 被写入 / 指令被改写；
- 进程内存在未签名的第三方模块；
- 方法入口指针指向游戏模块之外。

**这是无法回避的暴露面**，与"用了哪个功能"无关——只要加载了插件就存在。区别只在于：这是"修改游戏代码"，不是"对抗反作弊"。

### 2. 文件与部署物

游戏目录内属于第三方的东西：
- `d3d12.dll` —— ReShade 6.8 代理加载器（ReShade 官方安装方式）
- `vulkan-1.dll` —— 本项目构建的 Vulkan 加载器转发层（`vulkan_loader_forwarder.cpp`），`DllMain` 里设置 `VK_IMPLICIT_LAYER_PATH` 并把 `RESHADE_DISABLE_LOADING_CHECK=1`
- `endfield-enhancer-FPV.addon64` —— 插件本体
- `ReShade.ini` / `ReShade.log` / `AEEF.ini` —— 配置与日志

注意：`RESHADE_DISABLE_LOADING_CHECK` 关闭的是 ReShade 自己的加载检查，与 ACE 无关，但对外容易被误读，建议在文档里写明。

### 3. 运行时环境变量

转发层会设置进程环境变量。这是进程内行为，不涉及系统级持久化改动。

## 三、功能面（会改变什么）

### 改变游戏状态的（高风险）

- 自由相机 / FPV：接管相机，视点可离开角色、穿墙、飞出地图。相机位于角色不可达位置时，若游戏上报相机或角色所在区域，服务端有机会看到异常。
- 实体朝向写入：`RotatorComponent.SetRotation` 写角色视觉实体朝向，用完恢复。
- 玩家动作掩码：`AddActionEnableMask` / `RemoveActionEnableMask` 关闭角色常规动作，用于自由相机期间"人不动、镜头走"。这是对玩家控制器状态的真实修改。
- 光照体积流送跟随相机（默认关闭）：调用 `HGIrradianceVolumeManager.SetOverrideStreamingCenterByCamera()`，把光照体积(IV)的流送中心覆盖为相机位置。关掉 FPV 时把 `m_overrideStreamingCenterByCamera` 标志写回 0（纯内存写，不执行游戏代码）。
  - 实例获取：`HGManagerContext.get_currentManagerContext().ivManager`，每次动作前现取一次，避免用到随场景重建失效的指针。
  - 复位必须在游戏线程执行（`HookedPush` → `ConsumeReset`）：从渲染线程调用游戏代码会闪退，已实测确认。

### 未采用：让远处地形跟着相机细化

离线解析 `global-metadata.dat` 后确认，远处地形/物件是否细化由两组"每帧被喂一次"的输入决定：

- 地形：`HGTerrainGroundLayer.SetPlayerCenter`、`HGTerrainGroundLayerClipmap.SetPlayerCenter`、`HGTerrainDeformManager.SetPlayerCenter`、`GpuClothManager.SetPlayerCenter`
- 场景加载：`DynamicSceneGridDealer` 的 `m_streamingCenters` / `FillEnabledStreamingCenters` / `GetMinSqrDisOfCurrentStreamingCenters`，中心来自 `BaseGameScene.m_streamingCenter` 与 `PlayerCenterUpdater`

因为它们每帧被重新投喂，一次性设置留不住；要生效必须拦投喂，也就是必须新增内联钩子。三条候选路径的风险排序：

| 方案 | 目标 | 风险 |
| --- | --- | --- |
| 钩地形 `SetPlayerCenter`（2~3 处） | 图形模块，参数为纯坐标 | 最低；副作用是相机飞远后角色脚下高精度地形可能被卸载 |
| 钩 `BaseGameScene` 流送中心 | 场景加载入口 | 中高；可能远程触发区域事件，加载逻辑出错易崩 |
| 钩 `PlayerCenterUpdater` | 同时喂草地/水面/墨水模拟等系统 | 最高；等于对多个系统同时谎报"角色在哪" |

结论：本项目不新增钩子，三条均不采用；功能停在光照体积这一档，面板文案已按实际语义改写。分析脚本保留在 `tools/il2cpp_meta_probe.py`，可离线查询任意类的方法与字段。
  原先还有两套更深的实现（Detour `BaseGameScene.GetStreamingCenter` 改返回值；Detour `PlayerCenterUpdater` 的坐标入口并每帧覆写 `characterPositions[0]`，依赖硬编码偏移猜 NativeArray 布局），因为改的是游戏逻辑输入且写内存方式脆弱，已整体删除。

### 改变实体加载的（中风险）

NPC 剔除、LOD 降级、加载距离、世界距离：只影响客户端流式与渲染，但会让游戏看到的实体集合与设计不同，可能造成任务 NPC 不加载、区域表现异常，属于"异常客户端"特征。

### 只影响画面的（低风险）

SSR / HDR / 帧生成 / LOD 画质、UI 隐藏、截图、窗口增强、飞行 HUD、FPS 解锁（走 `Application.set_targetFrameRate` 与 `QualitySettings.set_vSyncCount`，是引擎自身接口，不写内存）。

## 四、建议

### 立刻可做

1. **加一个"合规模式"预设**：一键关闭全部会改动游戏状态的功能（NPC 剔除、LOD、加载距离、自由相机、锚点迁移），只保留画质与 HUD。默认走这个预设。
2. **收窄钩子面**：`npc_offcamera.hpp` 11 处钩子里，`HookedLodTick` / `HookedLodManagerTick` 这类入口已经能覆盖大部分行为，其余多为同一条链上的下游函数。合并后能显著减小被改写的代码页面积，同时也降低崩溃概率。
3. **文档明示**：README 顶部写清"本插件通过内联钩子修改游戏进程内的代码，可能违反用户协议、存在封号风险"，并区分"画面类功能"与"改变游戏状态的功能"。
4. **联机场景警示**：在自由相机 / FPV 面板里加一行提示——不要在联机副本、竞速或任何多人内容里使用。

### 中期

5. **降低部署面的可疑度**：`vulkan-1.dll` 转发层是文件级最显眼的第三方物（今天那次卡加载也正是渲染路径代理引起的）。若能用 ReShade 官方 Vulkan 安装方式替代，可以少一个自建代理 DLL。
6. **配置与日志默认落到 `%APPDATA%`**：`config_store` 目前优先写加载器目录（游戏目录）。游戏目录里的 `AEEF.ini` 是能被文件扫描看到的名字。
7. **版本与变更可追溯**：每次发版在 CHANGELOG 里写清"新增/移除了哪些钩子"，出问题时能自证。

### 长期判断

8. 账号策略：新版本先用自己的小号跑一到两周，再推到主号；不要同时开着 MAA 挂机与插件跑长时间挂机场景（叠加特征）；插件版本号与日志保留好，必要时是说明情况的依据。
9. 申诉层面的事实基础：本项目不联网、不跨进程、不读存档、不碰反作弊进程。如果被判定，依据只会是"进程内第三方代码"，而不是"作弊数据或对抗行为"。这一点在文档里写清楚，对用户是负责的。
